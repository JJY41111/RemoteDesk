# 跨地區從 iPad 連回 Windows 主機

RemoteDesk 原本只接受主機區網 IPv4，例如 `192.168.0.95`；這個位址離開家中網路便無法直接使用。現在新增只綁定主機 **Tailscale 網卡**的跨區模式。iPad 和 Windows 必須登入同一個 tailnet 並保持 Tailscale 已連線。不需在家用路由器開放 8443、9443 或 WebRTC 埠到公網。

## 啟動與連線

在 Windows 主機的 `C:\Users\johnl\Desktop\RemoteDesk\bridge` 執行：

```powershell
npm.cmd run preflight
npm.cmd run start:tailnet
```

`start:tailnet` 自動讀取目前主機 Tailscale IPv4，僅綁定該網卡的 HTTPS `9443` 與 CA 下載 `9442`；原始 H.264 TCP 僅在 `127.0.0.1:55445`。若 Tailscale 未連線會直接報錯，不會綁定公網位址。主機視窗會顯示本次 8 位配對碼；保持程序執行。

本次主機位址為 `100.124.244.122`，iPad Safari 網址為 **https://100.124.244.122:9443/**。位址可能在裝置重新加入 tailnet 後改變，屆時以 `preflight` 輸出為準。iPad 若顯示憑證警告，先確認 RemoteDesk CA 已安裝並設為信任；不要忽略憑證錯誤。這次重新簽發的主機憑證同時涵蓋家中 IP 與 Tailscale IP，CA 指紋為 `B8:06:CD:EC:CB:A7:7B:AE:C0:9C:BA:1D:AC:2C:F8:1C:3D:8E:7E:FD:06:82:94:DB:0C:E6:58:4C:04:E2:81:70`。如需重新下載 CA，僅在同一 tailnet 使用 `http://100.124.244.122:9442/ca.crt`，安裝前核對主機所顯示指紋。

Windows 目前另有區網模式監聽 `192.168.0.95:8443` 和 `127.0.0.1:5000`；跨區服務使用獨立埠，未停止原服務。若電腦睡眠、關機、Tailscale 斷線或本程序退出，iPad 便無法連線。目前尚未設定開機自動啟動。

### 09:27Z 影音低延遲安全回退與送出診斷

舊的 0–50 ms RTP 提示已由實機證實會讓 iPad 持續解碼卻停止呈現；本輪仍未重啟它。現有 Safari 18.7.8 CSV 顯示 `receiver_latency_supported=0`，因此頁面仍無法直接要求該版本縮短畫面接收緩衝。對支援 `jitterBufferTarget` 的瀏覽器，現有高緩衝時才介入的實驗控制增加安全回退：若已套用、解碼達至少 30 FPS 但 2.5 秒沒有呈現影格，立即清除接收端目標並關閉低延遲請求，頁面顯示原因。這只降低再次凍結時必須斷線的風險，不能預先證明 Safari 27 不會凍結或延遲會下降。

查出另一個底層診斷盲點：目前 node-datachannel 0.33.4 的 TypeScript 宣告包含 `Track.bufferedAmount()`，但實際 Windows native Track 物件沒有該方法，原本的 4 MiB 視訊背壓判斷永遠不執行；`PeerConnection.bytesSent()` 對本測試媒體串流回報 0，不能當作媒體實際送出量。已移除失效的佇列判斷，改在 CSV 記錄 `host_video_send_max_ms`（每秒最慢單幀原生送出呼叫時間）與 `host_video_input_kbps`（交給 RTP 前的 H.264 速率），與 iPad 接收流量、RTT、遺失和緩衝對照。這些數值仍不能直接量到 libdatachannel 內部佇列，故不能據此宣稱排隊問題已修好；需要下一份跨區 CSV 判斷。

Windows 輸入程式若 `SendInput` 失敗，現在每秒至多輸出一筆 Windows 錯誤碼，方便與「畫面有、操作無」現象對照，不增加正常操作輸出。Windows 建置、17 項單元、UI 模擬凍結自動回退、首次配對輸入 READY 隔離埠、真實 1080p 串流及影音切換測試通過。真實串流在同機 Chrome 可送約 60 FPS，不能代表跨地區 iPad 實測。預設 1080p60、LAN 路徑及音訊控制保持原設定。iPad Air M2 內建顯示器有 60 Hz 上限的[直接裝置評測](https://www.notebookcheck.net/Apple-iPad-Air-11-2024-Gen-6-review-The-powerful-Apple-tablet-with-an-identity-crisis.841801.0.html)；為避免多送無法呈現的幀，沒有盲目改成 70–80 FPS，後續以使用者實機呈現及負載為準。
