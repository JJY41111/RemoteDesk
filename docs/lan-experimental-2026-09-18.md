# 指定區網 IP 與效能試跑 — 2026-09-18

## 這一輪完成

- 傳送端支援 `--connect=<私人 IPv4>`；接收端支援
  `--listen=<本機私人 IPv4>`。兩者預設仍為 `127.0.0.1:5000`，不會意外
  對所有網路介面監聽。
- 只接受回環與 RFC 1918 私人 IPv4；拒絕公開 IPv4、萬用位址及主機名稱。
  接收端獨占指定的位址和連接埠，不會建立防火牆規則。
- 接收視窗的跨設備模式不再拿兩台電腦的 QPC 時間戳相減；改顯示可在
  接收設備自身量到的「收到封包至完成繪製」時間。整段實際繪製 FPS 與
  最長繪製間隔仍會記錄。
- 傳送端 NV12 轉換預先計算縮放座標，並把亮度與色度寫入合併到一次
  2×2 像素取樣。沒有改變既有色彩公式或 720p／1080p 的輸出大小。

## 實際觀測

`build.bat` 成功，沒有專案程式碼警告。以**同一台電腦**的私人區網位址
執行 1080p60 五秒測試，傳送端送出 278 幀，接收／解碼／繪製各 278 幀，
實際接收 55.63 fps、繪製 55.86 fps，未跳過已解碼影格；最長繪製間隔
280.19 ms。這證明指定 IP 的收發路徑可工作，但不是跨電腦測試，也沒有
達到穩定 60 fps。Windows 顯示了接收程式的防火牆許可視窗；本次沒有
替使用者變更防火牆設定。

在像素轉換優化後，另一輪同機回環 1080p60 測試，轉換平均 9.22 ms，
接收／解碼／繪製各 273 幀，繪製 55.17 fps，最長繪製間隔 473.50 ms。
前一輪區網位址測試的轉換平均為 13.90 ms，但兩次桌面負載與測試條件
不同，不能當作嚴格 A/B 效能證據。這個優化降低了單幀轉換成本，**尚未
解決偶發停頓，也不能宣稱 1080p60 已成為常態**。

接收端對 `--listen=8.8.8.8 --test` 在開視窗與監聽前回報拒絕公開位址；
預設回環監聽的 `--cancel-test` 正常結束。新增選項後的 1080p 同機
五秒路徑已驗證；完整 720p／1080p 跨設備回歸仍需要第二台電腦。
後續重測發現一個確定的啟動缺陷：桌面完全沒有變化時，傳送端一直等
第一張 DXGI 更新畫面，連線因而不會開始。修正是在 250 ms 後仍沒有
DXGI 畫面時，只用一次 GDI 桌面快照建立初始影格；後續更新仍由 DXGI
Desktop Duplication 擷取。此備援保留原有 720p／1080p 串流管線。

## 初始影格修正後的同機重測

以本機當時的私人區網 IP `192.168.1.100` 同時作為接收端綁定位址與
傳送端目的位址，不移動桌面視窗，兩次測試的日誌均確認走到
`capture: seeded first frame from GDI after DXGI timeout`。這仍是同一台電腦，
**不是第二台設備或真實區網往返延遲的證據**。

| 模式與時長 | 接收／解碼／繪製 | 接收 FPS | 繪製 FPS | 未畫出影格 | 最長繪製間隔 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 720p60，5 秒 | 301／301／301 | 59.97 | 60.04 | 0 | 32.28 ms |
| 1080p60，5 秒 | 301／301／301 | 60.02 | 60.15 | 0 | 34.96 ms |
| 720p60，30 秒 | 1795／1795／1795 | 59.78 | 59.80 | 0 | 127.79 ms |
| 1080p60，30 秒 | 1800／1800／1800 | 59.99 | 60.01 | 0 | 36.47 ms |

30 秒 720p 測試的平均封包接收至繪製延遲為 3.96 ms、P95 4.41 ms；
1080p 為 8.63 ms、P95 9.38 ms。這些數值**不含傳送端擷取、編碼及真正
跨電腦網路的時間**。720p 的 127.79 ms 最長停頓不能由平均 FPS 掩蓋；
偶發卡頓與動態場景仍需調查。1080p 最後一幀存成 1920×1080 BMP，
人工檢視有實際桌面、文字與正常色彩。

為了可重複測試，網路測試模式新增 `--duration=<秒數>`，範圍 1–300，
未指定仍是五秒；`--network-*-live` 模式不受影響。以上 30 秒結果用
`--duration=30` 取得。

## 未完成與安全邊界

- 仍沒有第二台設備的收畫面與真實網路品質證據；接收端的 Windows
  防火牆許可由使用者自行決定。
- TCP 串流未加密、未驗證對方身分，不適合公共網路或機敏桌面。
- 沒有遠端輸入、音訊或手把；目前不能稱為可遠端玩遊戲。
- 跨設備單向延遲須另設計時鐘同步或畫面事件量測，不能直接相減
  不同電腦的 QPC 數值。
