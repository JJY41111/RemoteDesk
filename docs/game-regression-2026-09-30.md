## 本輪處理

配對頁增加 `1080p：遊戲卡頓比較測試`，讓同一部 iPad、同一場景可選用主機 CPU 轉色路徑，與預設 1080p GPU 路徑對照。它保留 1920×1080 尺寸與位元率設定，可能較慢或略糊，因此仍是診斷選項。舊的啟動指令與虛擬手把仍可用，切換模式須斷線重連。

CSV 新增 `host_capture_update_fps`、`host_capture_update_age_ms`、`video_mode`。主機原本「送出 FPS」即使重複同一張舊畫面也可接近 60；新欄位以 DXGI 來源事件時間變化計數，指出擷取內容是否真的更新。滑鼠移動也可能觸發來源事件，所以此數值不是遊戲內 FPS。

已用隔離埠 8544/55444 驗證：CPU 模式配對成功、bridge 自動以 CPU 轉色啟動擷取、本機 Chrome 解碼約 720–879 幀，主機送出約 60 FPS；每次結束可產生主機封存紀錄。這是桌面測試，不能推論《蜘蛛人 2》下 CPU 路徑較好。12 項 Node 測試與介面測試通過。

## 下一輪驗收

重新啟動 bridge 載入新版配對選項。在同一遊戲場景、相同圖形設定與 iPad 網路下，各測至少 2 分鐘：先預設 `1080p：遊戲優先`，下載 CSV；斷線重連選 `1080p：遊戲卡頓比較測試`，再下載 CSV。主機效能紀錄會在每次斷線後自動封存；請保留兩份 CSV。比較 `host_capture_update_fps`、`host_sent_fps`、`rendered_fps`、視訊遺失與實際操作感受；若 CPU 路徑在遊戲負載下明顯較好，再決定自動切換或設為遊戲預設。若兩者都差，需往 DXGI 擷取與遊戲全螢幕呈現路徑調查。
