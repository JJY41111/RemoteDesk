# 本機 TCP H.264 傳輸驗證（2026-09-16）

## 範圍

將現有 H.264 編碼輸出，以長度明確的封包透過 TCP 從 RemoteDesk 擷取程序
送到獨立接收程序。目前只綁定 `127.0.0.1:5000`，不向區域網路或網際網路
提供桌面畫面。首輪只驗證封包；同日後續版本已加入接收端解碼與獨立預覽。

每個封包含版本、序號、1280×720 解析度、長度與時間戳；接收端檢查順序
與大小，避免把 TCP 的任意接收區塊誤當成完整一幀。傳送工作在獨立執行緒，
最多緩衝 16 個封包，過量時直接回報錯誤，不會無限堆積記憶體。
延遲量測加入後，封包版本已升至 3，增加同機 QPC 時間戳；傳送端與接收端
必須使用同一次建置的程式。

## 重現方式

1. 執行 `build.bat`。
2. 在第一個終端執行 `out\remote_desk_receiver.exe`。測試後手動按 `Esc`
   關閉接收視窗；或加上 `--test` 讓它在串流結束後自動關閉。
3. 在第二個終端執行 `out\remote_desk.exe --network-test`。
4. 比對 `runtime.log` 與 `receiver.log` 的封包數、位元組數與校驗值。

## 本次結果

- 建置成功，無專案程式碼編譯警告。
- 編碼端：提交、編碼、同程序解碼各 150 幀，`image=yes`。
- TCP 傳送端：150 個封包、1,193,010 bytes、校驗值
  `16936972065659433875`。
- 獨立 TCP 接收端：150 個封包、1,193,010 bytes、相同校驗值；正常結束。
- 原有 `--loopback-test` 回歸：提交、編碼、解碼各 150 幀，`image=yes`。
- 原有 `--record-test` 回歸：錄影 150 幀，游標繪製呼叫 946 次。

校驗值是測試用的 FNV-1a 資料摘要，只用來比對本次兩端收到的位元組，
**不是**安全驗證或加密。

## 接收端解碼與預覽追加驗證

後續加入 Microsoft H.264 Decoder MFT，在獨立接收程序中解碼收到的封包，
將 1280×720 NV12 轉成 BGRA，並在自己的 Win32 視窗顯示。接收工作在背景
執行緒；關閉視窗可中止等待連線或接收。

追加五秒測試結果：

- 傳送端：150 個封包、653,806 bytes、校驗值 `15850262740789951966`。
- 接收端：150 個封包、相同位元組數與校驗值；成功解碼 150 幀，
  `image=yes`，平均接收端解碼與色彩轉換時間 16.49 ms／封包。
- 測試模式將最後一幀存為 `out\receiver_last_frame.bmp`；已開啟檢查，
  能辨識桌面與視窗內容，不是純黑畫面。此影像與預覽視窗使用相同的
  BGRA 幀緩衝區；尚未做人工觀看整段動態預覽的驗收。
- `out\remote_desk_receiver.exe --cancel-test` 在沒有傳送端時，一秒後
  自動關閉接收視窗，程序以代碼 0 結束；等待連線的接收執行緒沒有卡住。

這仍是**本機 720p／30 fps 原型**。尚未測試跨電腦、1080p60、長時間穩定性、
音訊或遠端輸入，也沒有驗證或加密，不能當成可安全上網的遠端桌面。
