# 1080p60 接收畫質驗證 — 2026-09-18

## 目的與變更

原本的 1280×720、60 fps 接收畫面雖較順，但 2560×1440 桌面縮到 720p
時，文字與細節變糊。新增可選的 1920×1080、60 fps 模式，原本的 720p30
與 720p60 保留。1080p60 要求 H.264 目標位元率 16 Mbps；這是設定值，
不是本次靜態桌面測試的實際平均位元率。

接收端現在根據封包的解析度建立解碼器和視窗。H.264 解碼器讀到第一批
1080p 封包後，會要求重新選擇輸出格式；接收端改從解碼器提供的格式中
選擇 NV12，並預留 1088 行編碼高度可能需要的緩衝。測試期間也發現，
解碼出錯時的析構清理會呼叫已失效的畫面回呼，造成記憶體錯誤；已改成
異常時直接釋放解碼器，只有正常停止才排空並回呼。

## 建置與測試

`build.bat` 成功，未出現專案程式碼警告。先執行
`out\remote_desk_receiver.exe --test`，再執行
`out\remote_desk.exe --network-1080-60-test`。兩個程式必須是同次建置。

本機 `127.0.0.1` 五秒測試（2560×1440 來源桌面）：

| 指標 | 1080p60 結果 |
| --- | ---: |
| 接收／解碼／繪製 | 300／300／300 幀 |
| 接收／繪製速率 | 60.10／60.38 fps |
| 未繪製影格 | 0 |
| 最長繪製間隔 | 25.04 ms |
| 傳送佇列至視窗繪製 P95 | 12.35 ms |
| 桌面變化至視窗繪製 P95 | 28.09 ms（283 筆） |
| 總傳輸 H.264 資料 | 981,380 bytes |

1080p60 測試當下的 `out\receiver_last_frame.bmp` 為 1920×1080，人工檢視確認有桌面、游標、
文字與正常色彩，並非黑畫面或明顯色彩錯位。這張靜態截圖不能證明
快速移動時沒有壓縮模糊；後續測試會覆寫這個檔案。

同一套程式再做 720p60 回歸測試：接收／解碼／繪製各 300 幀，接收
60.08 fps、繪製 60.22 fps、未繪製影格 0。
720p30 回歸測試也接收／解碼／繪製各 150 幀，接收 30.02 fps、繪製
30.09 fps、未繪製影格 0。

## 尚未證明

- 接收視窗繪製約 60 fps，不等於其他設備的實體螢幕實際顯示 60 Hz。
- 目前只測同機回環 TCP，沒有跨設備網路、遊戲動態場景或長時間測試。
- 1080p 的 CPU 色彩轉換平均約 9.77 ms，解碼與轉換平均約 9.27 ms；
  在較慢的電腦上可能無法穩定 60 fps。
- 遠端控制、音訊、手把與跨電腦連線尚未實作。它目前仍是同機接收畫面
  原型，不是可直接遠端玩遊戲的產品。
