## 修改

網路串流的 GPU 轉色改為三個固定 staging 槽位。以 `D3D11_MAP_FLAG_DO_NOT_WAIT` 檢查結果；GPU 未完成時繼續處理擷取迴圈，佇列滿時跳過新的轉色請求。優先送出最新已完成畫面，過時結果只在確認完成後回收，不用無限制佇列補播舊畫面。

正常 GPU 完成速度很快，因此送出後最多用 1 ms 輪詢嘗試取回，避免下一次 DXGI 等待額外延後取幀。這個時間是輪詢期限，不是所有驅動 API 呼叫的硬性耗時上限。解析度、原本 GPU 色彩轉換與編碼位元率保持相同。軟體轉色與本機編解碼測試仍有原路徑。

RTP 樣本時間與來源時間戳取自該槽位送出轉色時，避免把舊影格重新標成現在的時間。新增主機紀錄：`gpu_readback_age_ms`、`gpu_queue_skips_total`、`gpu_stale_frames_total`。`gpu-async` 下的 `convert_avg_ms` 是主執行緒花費；GPU 完成等待另外看 readback age，不能把前者的下降直接當成端到端延遲下降。

依據：[Microsoft Map 非阻塞旗標](https://learn.microsoft.com/en-us/windows/win32/api/d3d11/ne-d3d11-d3d11_map_flag)、[Flush 的非同步行為與成本](https://learn.microsoft.com/en-us/windows/win32/api/d3d11/nf-d3d11-id3d11devicecontext-flush)。
