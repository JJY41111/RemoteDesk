# iPad 滿版操作介面 2026-10-02.2

連線後使用全部瀏覽器可用高度，上方保留 48px 工具列與安全邊界，功能、診斷與文字輸入放入可關閉的浮動選單。放大與移動視角留在工具列；150% 時可按不帶修飾鍵的反引號切換，按住不連續切換，文字輸入區仍能輸入反引號。切換時釋放遠端按鍵與滑鼠，清除未送出座標，避免按鍵卡住。

全螢幕按鈕請求整個頁面進入 Fullscreen API，保留工具列與輸入控制，支援標準及 WebKit 方法。瀏覽器拒絕時顯示原因，不假裝已全螢幕。退出全螢幕後恢復按鈕狀態。影片保持比例；平板與Windows的長寬比不同仍可能有黑邊，150%視角模式可放大並移動。

Windows Chrome 模擬 iPad 橫向1180×820、直向820×1180版面、進出全螢幕、150%縮放、拖曳、座標對應、快捷鍵單次切換、文字輸入保留與原有UI回歸通過。截圖位於 bridge/test-results/session-layout-*.png。此為本機瀏覽器驗證，Safari原生全螢幕與硬體鍵盤仍待iPad確認。

只更新網頁資產，重新載入頁面可取得，無需重啟9443或變更配對碼。未修改串流編碼、網路或音訊設定。

## 2026-10-02.4 鍵盤焦點修正

上一版將實體鍵盤文字框移至畫面外並縮成 1px。iPad Safari 聚焦可編輯文字框時可能退出網頁全螢幕；150% 放大後也會預設留在移動畫面狀態。現在「鍵盤控制」會啟用遠端操作、關閉功能選單、在放大時切回遠端操作，並聚焦可見的遠端畫面；實體鍵盤按鍵在全螢幕與 150% 放大時都走原鍵盤事件通道。診斷文字框留在功能選單中，不再隱藏到畫面外；CSV 的 keyboard_focus 同時記錄遠端畫面或診斷框焦點。

Windows Chrome 測試已驗證全螢幕、150% 放大下按鍵送進控制通道，且按「鍵盤控制」沒有退出全螢幕；原 UI 回歸測試通過。iPad Safari 實機尚待驗證。觸控鍵盤需要聚焦文字輸入框，舊版 Safari 對全螢幕文字框的限制可能仍會讓它退出；實體鍵盤不再使用該框。

## 2026-10-02.6 移除重複的全螢幕控制

主畫面網頁 App 現在會以 standalone 視窗開啟，使用者要求移除工具列的網頁 Fullscreen API 按鈕。已刪除按鈕、事件與樣式，保留版面填滿、150% 放大、移動畫面切換及鍵盤控制。前述全螢幕記錄是舊版歷史驗證，現行介面不再提供該按鈕。
